What UrbanHeat Analytics Does

A rigorous, research-grade tool for exploring documented heat observations — no data is invented.

📊

Temperature Analysis

Statistical summaries, distributions, and time-series charts for any documented heat measure (LST, air temp, heat index).

🗺️

Spatial Mapping

Interactive scatter maps overlaid on coordinates when latitude/longitude columns are present in your dataset.

🌿

Vegetation Correlation

NDVI and custom vegetation index analysis correlated against temperature values with Pearson/Spearman stats.

📅

Temporal Patterns

Daily, monthly, and seasonal breakdowns with date-range filters to explore heat patterns across time.

📋

Data Quality Reports

Transparent quality counts — how many rows are usable, missing, or invalid — before any analysis begins.

⬇️

CSV Export

Download the full analytical view (original rows + derived columns) for use in external research tools.

How to Use the Dashboard

Designed for researchers — every step is transparent and traceable to the source dataset.

1

Prepare your CSV

Export a CSV from your data source. The file should have a header row and include at minimum a temperature column. Max 50 MB.

2

Upload & document the source

Upload the file in the sidebar. Fill in the dataset name, URL, study area, acquisition date, and spatial/temporal resolution exactly as stated by the provider.

3

Declare the temperature measure

Select whether the column represents Land-Surface Temperature, Air Temperature, Heat Index, or another metric. Select the unit (°C, °F, K). Only one measure is analysed at a time.

4

Map your CSV columns

Assign columns to Temperature, Date, Location, Latitude, Longitude, and Vegetation using the dropdowns. Optional fields are skipped if not mapped.

5

Explore & export

Use the date-range and category filters to drill down. Download the annotated CSV for further analysis in R, QGIS, or other tools.

Deploy the App

Run locally from the zip file or deploy continuously on any container platform.

🐳 Local (from zip) Recommended

Unzip the project, build the Docker image, and run it. No Node.js or pnpm needed — just Docker.

# 1. Unzip and enter the folder cd Urja-main # 2. Build the image docker build -t urbanheat . # 3. Run (app on :8501) docker run -p 8501:8501 urbanheat # Open http://localhost:8501

☁️ Render (free tier) Free

Push to GitHub → connect to Render → it auto-deploys using the Dockerfile on every push.

# On Render dashboard: Service type: Web Service Runtime: Docker Port: 8501 Health check: /_stcore/health # Auto-deploys on git push 🚀

🚂 Railway Easy

One-click deploy from GitHub. Railway detects the Dockerfile automatically.

# Install Railway CLI npm i -g @railway/cli # Login & deploy railway login railway init railway up # Set PORT=8501 in Railway env vars

🤗 Hugging Face Spaces Free

Create a Docker Space on Hugging Face — perfect for research projects.

# Create new Space: SDK: Docker Push app.py, analysis.py, requirements.txt, Dockerfile # Add to Dockerfile: ENV PORT=7860 EXPOSE 7860
⚠️

Why not Vercel serverless directly?

Streamlit requires a persistent, stateful WebSocket server. Vercel's serverless functions are short-lived (max 60s) and stateless, so a Streamlit process will timeout mid-session. This Vercel site serves as the landing page / embed shell — the actual app runs on a container platform.
